# 운영 원칙 — 4대보험 명부 고용혜택 1분 진단기 (독립앱)

이 저장소는 고용지원금 Pro에서 분리된 **독립 서비스**입니다. 기존 고용지원금 Pro 저장소/배포/DB와 완전히 분리되어 있습니다.

## 자동 커밋·배포 (매번 묻지 않기)

사용자가 수정을 요청하면 아래를 **한 번에** 진행한다. 커밋할까요/푸시할까요/배포할까요를 반복해서 묻지 않는다.

1. 코드 수정
2. `npm run build` 실행
3. 빌드 성공 시 변경사항 커밋
4. `main` 브랜치에 push
5. Vercel Production 자동배포 확인
6. Production URL에서 핵심 기능 확인
7. 완료 후 커밋 해시와 배포 결과 보고

중단·보고 조건(이때만 멈춤):
- `npm run build` 실패
- 개인정보 유출 위험(주민등록번호 노출, 서버/스토리지 업로드 등)

금지:
- 강제 push 금지 (`--force` 금지)
- 기존 커밋 히스토리 재작성 금지

## 개인정보 보호 (필수)

- 파일/명부 내용은 브라우저 메모리에서만 처리. 서버·Supabase·스토리지 업로드 금지.
- localStorage/sessionStorage에 파일 내용·주민등록번호 저장 금지.
- 주민등록번호 원문 저장/전체 표시/복사 포함/로그 출력 금지 (마스킹만).
- 외부 AI API로 명부 내용 전송 금지.
- 새 분석/새로고침 시 메모리 데이터 정리.

## 계산 로직 원칙

- 판정·계산 로직(`src/domain/payrollDiagnosis.js`)은 임의로 변경하지 않는다.
- 지원금/세액공제 금액·계산식 임의 변경 금지.
- "최대 가능 추정 / 1차 진단 / 추가 확인 필요" 표현 유지, 중복수급·확정 단정 금지.
- 로직과 UI를 분리해 다른 SaaS 재이식이 쉬운 구조 유지.

## 표현 규칙

"확정", "무조건", "100% 가능", "반드시 가능" 등 단정 표현 금지.

## 기술 메모

- Vite + React 19, 정적 SPA. 서버/DB 없음.
- PDF: pdfjs-dist (동적 import, 워커 별도 에셋). 엑셀/CSV: xlsx (동적 import).
- Vercel: Framework=Vite, Build=`npm run build`, Output=`dist`.
- 서비스명은 `src/config/service.js` 한 곳에서 관리.
